## 主线程文件调用

`run_20261016_034358` 使用改动前的 runner，仅对 3 号伴随进程主线程跟踪 `read`、`write`、`openat`、`close`。跟踪文件保存在 Linux 文件系统，关闭该进程的阶段计时，其余三机保留阶段计时。相机图像由视觉工作线程读取，不包含在此统计中。

跟踪会改变调度和系统调用耗时；表中累计值用于定位同步访问成本。此次没有捕获单次超过 20 ms 的上述调用，不能据此排除其他运行中出现的长时间等待，也不能将调用耗时全部归因于存储介质。

此次任务取得 0、3 号的合格压力接触。到 180 s 仿真上限时，0、2、3 号已原生着地停机，1 号仍已解锁且没有着地确认，起点水平误差 13.833 m。恢复检查未通过。启动器停止了所有所属进程，并核对被跟踪子进程的 PID 与启动标识已消失。

## 按导航周期刷新日志

runner 在生成记录时仍立即序列化 JSON，保留记录顺序。去掉每条记录后的显式刷新，改为每个导航周期发送控制、处理本轮 ToF 后刷新；标准流缓冲区满时仍自动写出。退出时刷新末尾记录。

实时日志读取器按导航周期看到新增记录。`DRONE_PROFILE_RUNTIME=1` 的退出统计新增 `log_flush`，区分记录生成和显式刷新；`log_emit` 仍包含流缓冲区满时的自动写出耗时。阶段有嵌套，不能将各项直接相加。
