面向实施的数据路径

推荐准备的路径：
摄像头 → VI / ISP → VPSS 缩放与格式整理 → 容量一最新帧槽 → 单次 NPU 推理 → CPU 后处理/跟踪 → 带源时间戳与序号的目标结果 → 接口准入检查 → 有时效的伺服意图。
两颗 ToF / 可选 UWB / 飞控姿态 → 有限长度时序缓存 → 定位周期任务 → 带坐标系与协方差的估计结果 → 同一门控。

将驱动、推理、定位与输出发布拆成有清楚所有权的模块；不为每帧创建线程，不把锁跨整个推理调用持有。应用视觉 worker 一次只接纳一帧，期间允许最新槽覆盖旧等待帧。真实实现若让预处理、NPU、后处理各自排队，整个管线会新增缓冲，必须重新计算上界；本模型没有隐藏这些额外并发。

零复制是要验证的数据路径属性。VPSS 有取帧/释放 API，系统有物理地址映射与 cache flush API。[S10, S11] 官方说明融合预处理、外部像素格式、VPSS 输入对齐与 aligned_input 要匹配。[S7] 这些能力提供减少搬运的机会，但本研究没有验证指定 runtime 能直接绑定该帧物理地址。mmap 本身不能证明端到端零复制，映射后转成连续 ndarray、RGB、tensor 或 SSH 预览仍可能发生复制。

路径需要测量/验证预算方法
CPU 完整预处理VPSS/YUV → 用户缓冲 → RGB/resize/normalize → tensor → runtime 的隐藏上传/同步按每次 copy/转换记录源目的 bytes、stride、CPU 墙钟/线程耗时与所有权。不要把所有搬运隐藏在 npu_ms 中。
VPSS / 融合预处理输出 shape、planar/packed、pixel order、真实 width stride，对齐、量化归一化与参考输出一致减少 cpu_pre_ms 后，NPU 或 VPSS 时间/内存可能增加；重新测量整条路径，而非只减 CPU 输入值。
物理缓冲绑定候选runtime 同镜像支持的 DMA/tensor API、cache coherency、异步完成点、最后读者释放、池深度只有接口和实测都证明不发生额外 copy 时才能标记“已验证零复制”。未证明时填 cpu_copy_ms；共享帧引用不要重复计成多个独立 frame_bytes。
尺寸例子640×480 NV12 紧密一帧 460800 B；RGB 一帧 921600 B；320×320×3 BF16 张量 614400 B以上均是尺寸算术，实际分配使用 stride/align/plane length；按“独占分配”汇总 VB、模型权重、激活、张量和用户缓冲。仿真默认固定池预算零只表示未填，绝不表示板端无开销。

ToF/UWB 的总线阻塞和数据可观测性不在本计算模型内。nav_ms 是一个定位 CPU 任务的合成预算，不能证明两颗 ToF 能提供完整三维位置或方位。真实传感器采集需源时间戳、序号、质量字段和独立故障处理，再进入已有坐标/协方差门控。

超龄与重复目标不能继续驱动下游。新推理完成并不保证输入新鲜。输出应带 frame_id、t_sensor、t_publish、target_id、quality/valid_until；接受端按映射后的源时间计算当前年龄，拒绝超龄、重复序号与乱序，不用重新发布旧目标来“续期”。同一目标 ID 的新帧观测可以更新；重复的 frame_id/消息 seq 不可作为新测量。目标短时预测也要沿用最后真实测量时刻并限制预测期限，超期发布“无新鲜目标”状态。这里仅规定实现准备，不做飞行控制或动作执行。

两个策略都使用同一 CPU/NPU 调度、定位容量一等待槽与单视觉 worker。FIFO 只改变视觉等待槽为无界 deque；latest 覆盖待处理帧，绝不取消已经接纳的帧。CPU 上同时只有一个阶段；NPU 推理期间 CPU 可以做定位。此模型没有把 CPU 线程与 NPU 算力相加，也没有让另一视觉帧的预处理与当前 NPU 隐式重叠。

等待与完成是不同统计。queue_wait_ms 从帧可用到进入采集阶段；age_ms 到跟踪完成。p50/p95 为 nearest-rank，最大值来自已完成帧，没有样本为 null。窗口 [0,T) 内释放任务，允许恰在 T 完成及其零耗时后续阶段，T 后不排空队列。outstanding、overdue_at_end 和最旧未完成年龄单独报告，避免过载的未完成帧从延迟报表消失。

stale_completed 就是完成时严格超过 frame_deadline 的输出数。视觉 deadline_misses_observed 为完成违约＋窗口末未完成过期；视觉丢帧另计，比例的分母为生成帧数，不能把低违约比例解释为高成功率。定位违约从 release 起算；定位等待槽被覆盖的任务另外报 dropped 与当时已超期数。若应用要求每个定位周期都有输出，应把每次定位 drop 直接视为不满足要求。

为什么最新帧策略有内存上界，而实时性仍需测量

初始等待数 Q=0、在途数 A=0。每次到帧在 latest 下至多用一个新引用替换等待引用，所以 Q≤1；接纳只将一个引用从 Q 移到 A，A 在整个采集/预处理/NPU/后处理/跟踪结束前保持为 1；完成释放该引用。因此任意调度和有限服务输入下 Q+A≤2，应用模型帧内存≤2×frame_bytes＋fixed_memory_bytes。定位也最多一个等待任务和一个执行任务，且二者只存少量状态。FIFO 只要平均接纳速度长期低于到达速度，等待数便随观察窗口增长，没有统一上界。

这个证明仅约束模型持有的帧，不含驱动内等待、VB 池、tensor、激活、实际 RSS、调试图像、日志与结果历史。零复制时引用可能指向同一 VB 池，要按所有权避免重复计算。仿真保存年龄样本的 Python 内存会随样本数增长，它是 PC 观察器，不能称作实际应用的两帧内存证明。

容量一不保证 wait 或 total age 有绝对毫秒上界：CPU 阻塞、定位过载或长推理都可能让在途帧很旧。调度恢复时通常能取到最近等待帧，但这个等待在恢复前也可能很长。单帧服务已经大于期限时，换队列仍会产生 stale_completed，必须降低模型代价、降分辨率、改输入调度或改变可接受性能目标。

忽略突发的名义 CPU 请求负载为 [camera_fps×(capture+copy+pre+post+tracking)+nav_hz×nav_ms]/1000；名义 NPU 请求负载为 camera_fps×npu_ms/1000。本模型还串行接纳视觉，因此完整视觉周期本身也要考虑。各负载<1 只能作必要筛查，不能证明期限；CPU/GPU/NPU 占用率低也可能是单帧管线串行或等待导致。

开销与突发台架输入，不飞行：开启/关闭 SSH 预览、录像、日志；高目标数、无目标、运动模糊、总线迟延/丢包回放CPU 后处理/NMS/日志是否抢占定位？最新帧覆盖是否正确释放 VB？旧目标是否持续发布？
持续运行每个候选先暖机，再至少 10 min；最佳候选持续 30 min；记录温度/频率/内存。故障与延迟注入仅在台架或离线回放。是否热降频、内存泄漏、池耗尽；冷态通过能否延续到热态？

本模型的输入只填入板端测得的服务分布或明确的合成假设。npu_ms_pattern 与 bursts 能表达确定性尾部/突发，但不能取代带相关性的整段实测时间轴：内存带宽、cache、DVFS、驱动隐藏队列和 OS 抢占都不在事件模型内。

建议硬件选择门槛：全部待验证

下列值用于准备评估表，是本研究提出的工程门槛，不是 RM2027 官方标准，不是已验证的闭环安全指标。最终需按目标速度、距离、相机视场、执行周期与定位误差预算重新确定。当前 PC 阶段仅验证接口、调度、门控与报告；不据此宣布 Nano 已满足飞行任务。

拟议门槛建议初值通过依据 / 未通过时的实施选择
视觉结果时效有效新观测 ≥15 Hz；源采集→门控接受 p95≤80 ms、p99≤100 ms；硬截止 100 ms连续台架测量，超截止/重复消息接受数必须为 0。单帧延迟不达标优先缩输入、轻模型、VPSS/fused、验证搬运；降低 camera fps 不会缩短固有单帧推理耗时。默认仿真 100 ms 只到跟踪完成，未覆盖此真实门槛。
定位期限与数据时效15 Hz；release→done p95≤20 ms、max≤66.67 ms；建议样本中 deadline miss/drop=0记录 nav_release 与源输入龄，二者都满足；若主 CPU 阻塞定位，先缩短非抢占阶段、独立采集/有限队列，再考虑降视觉频率或更强伴随计算板。有限样本零违约不证明永远无违约。
控制消费者时效不接受超 100 ms 的视觉源测量或重复 frame_id；失去新鲜目标后在下一个消费者周期标记失效用重复、乱序、超龄、时钟映射未知回放验证。不能仅看平均 detector fps；不可发布旧结果新时间戳来续期。
CPU 余量10 min 单 Linux CPU 平均≤70%，1 s 窗口 p95≤85%；定位期限仍需单独通过同场景/热态/日志预览条件测量；占用率只作余量门槛，低占用不能证明低延迟。
内存与驱动池建议 MemAvailable 持续≥20 MiB、关键 VB/ION 池余量≥20%、不依赖 swap、不发生池耗尽；暖机后 30 min PSS 增长≤1 MiB结合动态池高水位与所有权检查，不仅看 RSS。任一泄漏/耗尽即停止加功能并修所有权；模拟两帧峰值不是完整板端内存预算。
模型与精度确切图转换＋runtime 运行成功；提出 INT8 相比参考集的召回损失≤2 个百分点召回门槛仅为量化回归初值，实际低误检/漏检率、关键点误差与伺服需求仍需定场景验收。BF16 精度较好但速度/内存必须另测。
热态持续性能30 min 后视觉 p95 相比暖机稳态增长≤20%，且仍满足上述绝对期限同时记录时钟与温度，按供应商器件允许温度/实际散热判断；若仍超期再评估升级板卡，同时比较重量、功耗和接口。

持续过载例子中 latest 能将缓存限制到两帧，但有效输出约 13.9 Hz、p95 大于 100 ms，按上面的建议视觉门槛仍不通过。这正是不能用“内存有界”代替“视觉与定位已满足任务”的情况。基线通过的是合成输入下的调度示例；ToF 可观测性、识别质量、UWB 时钟与射频、控制闭环需独立实验。
