## 航路与起降

机库起点位于菱形托盘内，四架分别沿中心的 X、Y 轴偏移 0.16 m。托盘外圈边框比支撑面高约 40 mm。净空检查覆盖四个起点、48 个机体圆周支撑采样点、起飞包络、24 条编队航段及 5 条退出航段。

`vertical_takeoff=true` 时起飞阶段发送竖直上升速度。接触后先经过 `retreat_exit=(10.3, 2.6, 2.3)` m，再进入各自待命位置，避免横穿已到达的成员。

返航末段采用 `sequential_landing=true`、`landing_order=[3,2,1,0]`。等候机留在分散航路位置；当前机先到起点上方，再降到支撑面上方 60 mm 对准。水平误差不超过 25 mm、水平速度不超过 0.10 m/s，并保持本地结构定位有效 0.5 s 后下降。当前机确认着地且解除武装后轮换，下一架获得完整阶段时窗。降落中止后各机在分散位置下降。

`static_armor_localization=true` 将已知 CAD 装甲中心与相机 PnP 位姿联合用于位置、航向融合。观测按曝光姿态及速度回退；超过 150 ms 的延迟、重复曝光和创新超限观测被拒绝。该配置适用于固定装甲。

`bounded_landing_relocalization=true` 允许低速降落对准时进行多帧地形恢复：匹配必须满秩、至少 24 个内点，原始 XY 修正不超过 0.30 m、航向修正不超过 0.10 rad。截断位置重新建立对应面，保留至少 80% 内点且 RMS 不超过 35 mm；不同曝光的候选一致性保持至少 50 ms 后才融合。每次 EKF 实际修正仍不超过 XY 0.15 m、航向 0.10 rad。已记录的整队试验中，该分支接受次数为 0。

可选 `landing_yaw_rad` 数组按机号指定降落朝向，只在逐架降落的当前成员上生效；下降前还要求航向误差不超过 0.10 rad。默认地图未配置该数组。

## 检查与运行

在项目根目录使用 PowerShell 7。STEP 转换依赖见 `simulation/requirements-cad.txt`；重建命令复用本地装配缓存，`--extract` 重新展开源 STEP。

```powershell
$ErrorActionPreference = 'Stop'
& '.venv/Scripts/python.exe' -m simulation.import_rmuc2027
if ($LASTEXITCODE -ne 0) { throw '场地重建失败' }
& '.venv/Scripts/python.exe' -m simulation.check_map --output 'build/rmuc2027/clearance.json'
if ($LASTEXITCODE -ne 0) { throw '场地净空检查失败' }
wsl -d Ubuntu-22.04 --exec /usr/bin/python3 '/mnt/d/Robomaster code/drone/simulation/tests/bounded_trial.py' --sim-seconds 220 --mission team_contact
if ($LASTEXITCODE -ne 0) { throw '仿真执行失败，请检查运行目录中的日志' }
```

Gazebo 服务器提前退出时，试验脚本生成 `failed_trial.json` 并回收运行进程。

相机检查使用 Gazebo 实际图像和生产 PnP 检测器，入口位置误差为 0.94 mm，重投影误差为 0.36 px。180 g、半径 52 mm 的球形探针从装甲上方 0.8 m 自由落下，板端峰值为 259.34 N。
