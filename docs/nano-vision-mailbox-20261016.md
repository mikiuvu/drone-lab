# 视觉消息锁与提交拒绝测量

日期：2026-10-16。实现：`32e1216`。平台：RV Nano、四机 Gazebo/PX4 micro 仿真。

## 消息交换

视觉工作线程处理一帧，同时保留最新待处理帧和最新结果。控制线程的 `submit`、`poll` 使用 `try_lock`，锁忙时立即返回，避免等待工作线程。

耗时样本数组扩容改用独立统计锁；结果发布在消息锁内交换数据，旧结果在解锁后释放。替换待处理帧时，旧请求移到局部对象，在消息锁外释放。轮询取出结果后立即解锁，再检查曝光时效。统计快照同时锁定两组数据；三个公开接口由同一控制线程调用。

增加三项计数，并写入负载输出的 `vision_pipeline`：

| 字段 | 含义 |
|---|---|
| `submit_invalid` | 时间戳为零，或不大于上次成功提交时间 |
| `submit_busy` | 提交时消息锁被占用 |
| `poll_busy` | 取结果时消息锁被占用 |

runner 在成功提交后才推进 `requested_frame_seq`，锁忙后可在下一个 20 ms 导航周期重新读取最新相机帧。负载程序在每个相机周期只提交一次，因此提交拒绝会减少其接收帧数。

## Nano 负载

基线为 ToF 曝光姿态补偿后的 `39a4954` 二进制；候选为 `32e1216`。二进制、图像、地形、观测和候选源码均按清单核验 SHA256。

候选的全部拒绝均等于 `submit_busy`，`submit_invalid` 为零。180 秒接收并完成 5,398 帧，消费 5,397 帧，无处理失败、陈旧/未来结果、待处理帧替换或结果替换，完成频率约 29.989 Hz。峰值 RSS 为 21,744 KiB，最高温度 61.576 °C。

三组均无跳过 tick，ToF 接收数分别为 2,701/2,701、2,701/2,701、8,101/8,101，ToF P99 分别为 13.285、13.311、9.301 ms。提交耗时 P99 分别为 0.03224、0.03380、0.03276 ms。调度截止时间计数分别为 199、339、134。

这些测量确认了偶发拒绝的锁竞争原因，但未证明缩短临界区带来稳定的吞吐或 CPU 收益，严格 20 ms 导航仍未通过。历史 180 秒测试的 3 次拒绝不能与本次 2 次拒绝构成可靠的改善结论。

主机 OpenCV 16/16 项通过，无 OpenCV 算法测试 14/14 项及 IO 测试 1/1 项通过；补充的最终视觉用例通过。测试覆盖同步/异步结果一致性、曝光协方差所有权、无效时间戳、提交拒绝计数、运行期间统计快照及最新帧替换后的计数守恒。Nano 的 `test_vision_worker` 返回 0，前后启动 ID 一致，临时上传目录已清理。

运行 `run_20261016_020156` 在 79.701 s 进入 ABORTED，0、2、3 号取得合格接触，1 号未取得；四机均原生着地停机，严格恢复检查通过，最大起点水平误差 0.05839 m。
