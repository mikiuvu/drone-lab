从桌面实验开始

适用：DM-FC01 + LicheeRV Nano + 两颗 VL53L5CX。通过 Drone Lab 完成硬件数据采集、观察和调试；四机仿真见Gazebo 操作说明。

录制与回放：打开“① 实时数据” → “演示数据” → “开始录制” → 等几秒 → “停止录制” → “停止数据源” → 到“③ 日志回放”打开刚才的日志并播放。合成数据使用 DEMO 标记。

软件入口

用途入口说明
飞控配置与姿态观察④ 软件工具 → QGroundControlv5.1.5，本地安装；USB 连飞控。
Nano 终端、SSH 和文件管理④ 软件工具 → MobaXtermPersonal 26.5，便携版。SSH 连接后左侧为 SFTP 文件面板。
TF 卡系统写入④ 软件工具 → Rufus4.15 便携版；你选择 TF 卡及 .img，再启动写入。
代码与调试④ 软件工具 → VS Code使用已有 VS Code，项目有独立 Python 3.12 环境及运行/测试配置。
Nano 程序编译④ 软件工具 → 重新编译 Nano 程序后台使用已有 WSL2 Ubuntu 22.04 和配套 RISC-V musl 工具链。

第 1 步：电脑连接飞控

  1. 本阶段只接飞控 USB，在桌面操作，不连接电机。
  2. 打开 QGroundControl，等待识别。先记录现有固件名称/版本，缓慢转动飞控，看姿态变化。
  3. 无需为了试数据立即刷固件。若确需刷写，本地 firmware 目录有达妙提供的 PX4 V1.15 与 ArduCopter 固件；先核对硬件版本和现有固件。QGC 的“固件”页面选择自定义文件，刷写过程由你启动。
  4. 要在 Drone Lab 看飞控数据，先让 QGC 断开该 USB 串口，然后在“① 实时数据”刷新串口、选中实际 COM 口、选择 MAVLink 输出对应波特率，点击“接收飞控数据”。该串口入口接收飞控数据。
  5. 蓝牙 COM 口不等于飞控。拔插飞控对照设备列表确定实际端口。没有 COM 口时先检查数据线及 Windows 设备管理器，不要盲目安装一批驱动。

第 2 步：启动 Nano

  1. 准备 Nano、专用 TF 卡及读卡器、稳定的 USB 电源、3.3 V 逻辑 USB 转 TTL 模块。核对板卡 W/E/WE 版本。
  2. 在“④ 软件工具”打开官方镜像目录。已解压：2026-01-14-16-03-d4003f.img，来自 Sipeed 官方发布。确认适配板卡后，用 Rufus 选择此镜像和目标 TF 卡。写入会清空所选卡，必须核对磁盘。
  3. 写卡后将卡插入 Nano，通过 USB 电源供电。
  4. 打开 MobaXterm → Session → Serial，选择 USB 转 TTL 对应 COM 口，115200 波特率。接线按 Sipeed 文档核对：UART0 A16 为 Nano TX、A17 为 Nano RX、共地；TX 接对方 RX。只接逻辑通信线，供电按板卡手册。
  5. 使用镜像文档给出的登录信息，按实际 W/E/WE 板型配置网络。首次联网可能需要少量终端操作，MobaXterm 为其提供图形会话管理、复制粘贴和文件面板。
  6. 把 Nano 的 IP、用户名、密码填到 Drone Lab“② Nano 连接与部署”。点击“检查 Nano 与设备列表”，应看到 riscv64、系统信息及可用设备。首次 SSH 会显示主机密钥指纹，需要确认是自己的设备。密码不会写进配置文件。

网络、引脚复用与设备路径取决于板型和镜像。若查不到 /dev/i2c-*，按官方外设文档先启用相应总线。

第 3 步：接入一颗 VL53L5CX

  1. 先核对商家载板：供电范围、I²C 上拉到几伏、SDA/SCL/LPn 引脚。某模块支持 5 V 供电不代表 I²C 可以接 Nano 的 3.3 V 信号脚。
  2. 连接一颗，保持第二颗禁用。检查 Nano 后，从下拉框选择真实 /dev/i2c-N，地址默认用 7 位 0x29，8×8 帧率先用 10 Hz。
  3. 点击“上传并开始采集”。程序自动上传、SHA256 校验、初始化 ST 驱动及传感器内部固件；错误会出现在界面日志。
  4. 到“① 实时数据”看区域数值。移动一本书，检查距离随之变化；录制一段日志。

第 4 步：第二颗与飞控一起采集

第二颗建议先接独立 I²C 总线，同样使用 0x29。同总线方案需要在硬件端分别控制 LPn 并分配不同地址，再填写对应配置。

飞控可以继续 USB 接电脑；也可以把 MAVLink 遥测口连接 Nano 的可用 UART，填写“可选飞控串口”和波特率。不要占用 Nano 启动控制台。使用 Nano 转发姿态时，先停止电脑直连飞控，避免混合两路来源。

“停止数据源/停止 Nano 操作”会尝试结束该次启动的采集进程，关闭传感器测距。断网后远端进程未必立即退出；重连后如显示已有采集进程，使用 MobaXterm 检查。程序只允许一个采集实例。

怎么看数据

  • 热力图单位 mm，状态 5/9 且距离大于零视为有效；灰色是无有效目标。原始状态、目标数量、信号、环境光及 sigma 均保留在实测日志。
  • 画面默认旋转 180°用于传感器光学反转，可取消；日志始终保留驱动原始区域顺序。机体外参单独标定。
  • 2 秒未更新会标记过期。帧率是电脑接收速率，不是精确传感器曝光频率；序号缺口只表示接收记录缺口，不等于全部传感器漏帧。
  • 测距时间是 Nano 发现数据就绪的单调时钟；姿态源时间是飞控开机时钟。二者尚未同步。USB/SSH 传输延迟与姿态插值需在算法阶段单独验证。
  • 日志保存在 logs，DEMO/LIVE 分别命名。回放支持暂停、倍速、拖动进度；CSV 导出为一行一个区域，便于查看统计。

调试

VS Code 的运行与调试面板可以启动桌面实验台，在 Python 代码上打断点；任务面板可运行测试和交叉编译。Nano 端源代码在 nano，Windows 界面在 app。C 程序提供打印日志和本地交叉编译；远程 C 单步调试需要配置板端调试器。ST 和 MAVLink 第三方源码保留在 vendor，附带各自许可证。
