# OFFBOARD 控制流连续性

日期：2026-10-15。平台：Gazebo/PX4 四机仿真、LicheeRV Nano riscv64。

## 短暂停漏判

`run_20261015_185934` 在起飞阶段暂停 0 号伴随程序 1.8 秒现实时间。PX4 原生日志显示其于 11.284 s 退出 OFFBOARD 并进入失效保护，12.404 s 随参考恢复回到 OFFBOARD。

伴随程序没有捕捉到这段原生失效状态，心跳间隔也没有达到已有的 3 s 门限。程序继续了接近和接触任务，直到 23.061 s 因持续贴地而判为无法继续任务；PX4 最终在 44.484 s 确认该机停机。

该运行最终取得全队停机确认，但遗漏了暂停后的控制连续性故障。

## 发送间隔检查

伴随程序以本机单调时钟记录成功提交到 UDP socket 的 OFFBOARD 参考。监测仅在收到已解锁、OFFBOARD 心跳并实际发送参考后启用，参考发送间隔达到 500 ms 时锁存 `setpoint_gap_latched=true`。当前 SITL 启动器也将 PX4 的 `COM_OF_LOSS_T` 设为 0.5 s；本机间隔使用现实时间，飞控日志使用仿真时间。

新心跳和新参考不能清除已经发生的中断。程序记录 `OFFBOARD_STREAM_GAP`，终止原任务，停止 ARM/OFFBOARD 和任务参考，依据当前原生反馈请求 LAND，确认着地后才请求解除武装。普通心跳断流和原生失效保护继续保留各自的原因。

UDP 发送成功确认本机 socket 已受理数据；接收与执行仍由 PX4 原生日志核验。状态包和控制日志同时记录 `setpoint_gap_latched`。

## 1.8 秒注入复测

`run_20261015_190953` 在 TAKEOFF、0 号确认已解锁且未着地时暂停同一伴随进程 1.8 秒。进程恢复后记录 `OFFBOARD_STREAM_GAP`，原生失效锁存和 3 s 心跳间隔锁存均为 false，表明该次由发送间隔检查识别。

| 原生日志指标 | 漏判对照 | 发送间隔检查 |
|---|---:|---:|
| 最后一条 OFFBOARD 输入 / s | 23.058 | 10.811 |
| 12.5–16 s 的 OFFBOARD 输入记录数 | 35 | 0 |
| 0 号着地确认 / s | 44.436 | 14.124 |
| 0 号停机确认 / s | 44.484 | 14.162 |
| 全队 ABORTED / s | 48.401 | 27.241 |

两次运行的起飞时刻和后续轨迹不同，表中时间分别属于各自原生日志，不能当成严格配对的耗时基准。OFFBOARD 输入数量是 ULog 中保存的记录数。

故障事件的 `sim_time_us=10821000` 是恢复处理时已消费的输入时间戳，可能落后于 Gazebo 当前时刻；不能用它减去注入时刻推算现实检测延迟。500 ms 门限的边界由单调时钟单元测试核验。

复测四机均取得原生着地、未解锁以及伴随停止时未解锁确认。失效后和全队恢复后没有 ARM/OFFBOARD 请求，全部解除武装请求对应同一控制周期的新鲜着地反馈。
