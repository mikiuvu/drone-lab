# Companion integration contract

Executable: drone_companion_runner. Four independent processes, vehicle 0..3.

CLI: --vehicle N --config simulation/config.json --map simulation/maps/calibration.json --runtime simulation/runtime --duration SECONDS [--offboard] [--arm]. Duration 0 runs until SIGINT/SIGTERM. --arm requires --offboard and valid current estimates; no serial/hardware transport exists. Ports are loopback-only: observations 16000+N, peer estimates 17000+N, MAVLink bind 14540+N, PX4 destination 14580+N. Override only numeric ports with --mavlink-local-port and --mavlink-remote-port if parent config differs.

Map schema: walls [{x1,y1,x2,y2,z_min,z_max}], spawns [{id,x,y,z,roll,pitch,yaw}], optional room.floor_z, optional terrain_triangles_file. The terrain path is relative to the map JSON and contains raw little-endian float32 values with shape N×3×3. It is static prior geometry exported after the full STL transform; it is not simulator truth. The current RMUC mesh is expected to be about 124,965 triangles and 4.50 MB of raw vertices. The loader rejects malformed files, nonfinite vertices and degenerate faces. It builds a bounded BVH and uses first-hit ray association with a 0.35 m depth gate without normal orientation filtering; downward 20 degree ToF rays are roll/pitch compensated through the full mount and body attitude. The BVH stores reordered triangles and does not retain a second triangle index array. Initial spawn is read once. targets and target poses are never read. The calibration map defines a room; the RMUC mesh map uses the documented 2026 reference geometry.

Mission config optional root object: mode defaults to localization; only mode=armor enables armor guidance. vehicle_start_delays_s may map vehicle strings "0" through "3" to nonnegative simulation seconds. Each vehicle uses its own vehicle_waypoints entry when present; an empty or absent entry produces hover. Structural peer gating and covariance floors remain active.

Terrain association accepts all mount azimuths and triangle winding signs, including vertical faces. The axial ray parameter is preserved after mount rotation; body X and normal Z do not gate returns. Online gates: axial residual <=0.35 m, point-to-plane residual <=0.15 m, >=8 associated returns, at least two normal directions separated by cross-product magnitude >0.20, eigenvalue cutoff max(0.1, largest*1e-3). Full-rank validity uses measured information only. Final per-frame xy correction >0.15 m or yaw correction >0.10 rad rejects the frame without refreshing structure timestamps. Terrain absolute-reference freshness is capped at 0.5 s. These gates do not guarantee immunity to repeated small incorrect associations.

Actual 124,965-face benchmark in WSL Ubuntu-22.04: raw file 4,498,740 bytes; TerrainMap sizeof=72 bytes; vector capacity storage=5,126,100 bytes (~4.89 MiB), excluding allocator overhead and transient construction copies. 100,000 distributed downward rays: 96,474 hits, ~66,453 rays/s (~15.05 us/ray) on the desktop host. This is not RV timing. Construction temporarily retains multiple triangle vectors and an index array; budget peak memory beyond resident storage. Four independent processes each hold their own map. Optional benchmark: test_companion path/to/terrain_triangles.f32. Default ctest has active assertions and tests estimator fusion for 0,+120,-120,180 degree mounts, both vertical-face windings and trust-region rejection.

Shared config optional companion object: tof_mounts array of exactly three entries, each {translation_body_m:[x,y,z],yaw_rad,pitch_down_rad,roll_rad,horizontal_fov_rad,vertical_fov_rad,min_range_m,max_range_m}. Default yaw 0,+120,-120 degrees; pitch_down 20 degrees. Axes body FLU; optical +X forward, image right -Y, image down -Z. depth distance_m is Gazebo axial depth, NOT radial distance. 8x8 cell centers use (u-3.5)/4 * tan(FOV/2). The measured pixel endpoints are transformed by full mount and body attitude before finite wall segment and z interval matching.

companion.camera: {fx_px,fy_px,cx_px,cy_px,strip_center_separation_m}. Default separation 0.135m is the calibration strip centroid spacing, not panel width. Pixels alone select the target. Projection range assumes front-facing geometry; target identity is unknown. Camera metadata must carry sim_time_us and frame_seq matching the PPM comment. The camera pipeline uses the strip detector.

Observation UDP schema1: kind tof (sensor,distance_m[64],valid[64]); kind uwb (peer,range_m,bearing_rad,valid); kind height_assist (z_world_m, source SIM_HEIGHT_ASSIST). Each carries vehicle and sim_time_us. That last scalar supplies the height assistance input. No true xy/yaw or velocity is accepted. LOCAL_POSITION_NED, GLOBAL_POSITION*, HIL_STATE*, SIM_STATE are ignored.

If the launcher writes runtime/companion_config.json, the runner uses its active sensor_contract values for ToF origins, yaw, pitch, FOV, camera size and camera FOV. This takes precedence over built-in sensor defaults and prevents x500/micro mount assumptions. The PX4 attitude is converted to ENU and aligned once to the configured spawn yaw; this is an estimator initialization convention. PX4 EV yaw fusion must be enabled only when the parent EKF configuration intentionally consumes the published yaw. With vertical-only or horizontal-position-only EV fusion, the corresponding unused fields remain evaluator outputs and are not treated as fused truth.

Each process sends source ESTIMATE, kind estimate, timestamped ENU pose/velocity/covariance/validity to other peers. It writes companion_N.jsonl with estimate, control intention, fusion reports, command ACK and source labels. height_assisted labels live scalar assistance; vz_derived_from_height labels height finite differences. Positive vertical covariance is an explicit simulation assumption.

Build and core test results are recorded in README.md; Gazebo/PX4 flight results are recorded in ../docs/status.html and ../docs/terrain-localization.html.
