Nano 采集器实现审计

日期：2026-10-02 · 工作区：D:\Robomaster code\drone · 范围：现有 C 采集器、原生测试与运行契约 · 未连接硬件

采集接口：双 VL53L5CX 使用 schema=1 JSONL 和 64 区域数组；MAVLink 接收姿态与心跳。采集器处理输入校验、失败退出、管道背压、部分 I²C 读取、初始化中断和双传感器启动超时。PC 原生故障注入与 RISC-V 静态交叉编译通过。

1. 证据与固件身份

实现证据来自当前本地文件：nano/main.c（main、emit_tof、poll_mavlink、prepare_output），nano/platform.c（RdMulti、WrMulti、WaitMs），nano/platform.h，以及已安装 ST ULD 的 vendor/stm32-vl53l5cx/modules/vl53l5cx_api.c。首次理解及编辑前已使用 CodeGraph；索引为本地工具数据。

固件 JSON 记录的身份为 board_id=7140、git_identity=v1.15.0-6-gb8c6373f7f。该身份待实物读取核实，不能直接用主线 PX4 文档推定其外部定位入口、MAVLink 流配置、模式、失效行为或参数。采集器只解码 ATTITUDE 和 HEARTBEAT，尚不读取 AUTOPILOT_VERSION，也不校验上述身份；后续协议联调需以此定制分支的源码和实机记录为准。

2. 已确认的问题与修复

位置与原问题当前行为验证
main 的 strtoul(...,NULL,...) 接受尾随垃圾、符号和转换截断；波特率直到传感器初始化后才拒绝。parse_unsigned 检查首字符、完整消费、errno 和 UINT_MAX；parse_sensor 要求数字总线后缀与合法 7 位地址。支持的五种 baud、非空 /dev/ 串口路径在硬件访问前校验。串口打开/配置在传感器初始化前完成。负数、前导空白、尾随字符、32/64 位溢出、空串口、非法路径、重复传感器均返回 2；不存在的串口返回 5，传感器初始化计数为 0。
poll_mavlink 的读取失败只清 running；主程序可能返回 0。断开后的零读取未处理。函数返回错误种类；检查 poll 的 ERR/HUP/NVAL、read 的零返回与致命错误。EAGAIN/EWOULDBLOCK/EINTR 为临时状态。主程序保留失败码。每次最多读取 4×2048 字节，主循环在传感器前及每颗之后接收 UART。注入 read(EIO)、无效 fd、伪终端断开；主程序均返回 5并进入传感器清理。
逐段 printf、行缓冲 stdout 会等待下游；ferror 只停止循环而可能返回 0。append_record 在 4096 字节内组装完整行；stdout 设为非阻塞，每行单次 write。管道行长不超过查询到的 PIPE_BUF；拥塞、断开、溢出或短写返回 6。成功写入后才推进 ToF sequence。未读取的 4096 字节 Linux 管道触发失败且仅含完整 JSON 行；破损管道返回 6；注入短写不推进序号。最大字段存储值行长 3278 字节。
ST 的 vl53l5cx_check_data_ready / vl53l5cx_get_ranging_data 累积读错误后仍使用 temp_buffer；多块传输失败可能留下旧头或半帧。RdMulti 在读取前初始化目标缓冲区，任何分块失败时清除整个请求范围；非完整 ioctl 消息计数转为 EIO。io_errno 锁存后续失败，直到明确进入清理时重置。600 字节成功分 3 块；第二块失败使整个输出为零；已完成第一块计入字节统计；后续读写不再调用 ioctl。短消息返回 EIO。
初始化各步骤未检查停止请求；第二颗初始化耗时可能让第一颗过早触发 5 秒看门狗。start 返回失败后可能已启动硬件却不执行 stop。每颗平台保存停止标志与初始化期限，调用间检查；主程序阶段间检查 running。全部启动后统一设 last_frame。start 调用前标记需清理；即使 start 报错仍尝试 stop。第一颗初始化中停止，不初始化第二颗；第二颗模拟增加 6 秒初始化时间仍正常采集；start 失败仍调用一次 stop。
WaitMs 忽略非 EINTR 的 nanosleep 错误；清理忽略 stop 失败。等待失败传播；等待和传输之间检查取消与期限。清理每颗独立设 250 ms 调用间预算，取消标志不影响清理；stop 失败明确记录，原本成功退出改为 4。注入 EINVAL、停止标志、过期期限；失败传播和清理退出码通过。

初始化期限为每颗 30 秒，清理预算为每颗 250 ms，均为实现准备的初始值。它们只在平台调用之间检查，不能中断已经进入内核的 I²C ioctl；尚未实测这些值是否适合实际模块、I²C 频率及定制内核。

3. 兼容字段与时间契约

未改变 schema、记录 type、sensor=0/1、64 个区域数组、默认 8×8/10 Hz、最多两颗传感器或只接收 MAVLink 的约束。原 read_end_us 现在由采集循环在 ST 数据读取与解码返回后捕获，不再于输出格式化时取样。新增字段由现有 Python validate_record 保留。

字段精确定义不能由它推出的结论
ToF source_time_us / time_basis=nano_data_ready_poll成功检测到 ready 后、调用整帧读取前的 Nano CLOCK_MONOTONIC 微秒值。不是曝光中点、测距产生时间或硬件中断时间。调度、I²C 与轮询可能使它变晚。
poll_start_us开始此次 ST readiness 查询之前的 Nano 单调时间。不会反映上次循环到本次查询之间所有原因；需跨帧比较并统计。
read_start_us、read_end_us、data_read_us整帧 ST 读取入口、返回点与差值；目前 read_start 与 source_time 使用同一取样值。data_read_us 包含 I²C 传输、驱动等待和 ULD 解码，也受 OS 调度影响；不是单纯总线传输时间或 SG2002 推理耗时。
i2c_read_payload_bytes_total / i2c_write_payload_bytes_total当前进程中该传感器成功完整分块的载荷字节累计，包括初始化与 readiness 查询；错误后的已完成块也计入。不含寄存器地址、设备寻址、ACK、重启条件等总线开销；失败 ioctl 的部分物理传输字节未知。不能直接当作线路利用率。
sequence、sensor_streamcountsequence 为成功输出的每传感器本地序号；streamcount 为 ST 驱动读到的传感器计数。本地序号不会计量传感器未被读取的全部帧；进程重启归零，传感器计数可能回绕或重启。当前不检测传感器重启。
ATTITUDE source_time_us / time_basis=fc_bootMAVLink 的原始 time_boot_ms ×1000。不与 Nano 单调时间共享纪元；FC 重启、32 位回绕、延迟和乱序尚未分类或展开。测试确认原始时间回退仍如实输出。
nano_rx_monotonic_usread 返回当前 UART 字节块后的 Nano 时间；同块内记录共享时间。HEARTBEAT 也新增此字段。是用户态字节块接收时间，非飞控发送时间。UART 内核积压会增加误差；不能直接拿来当姿态测量时间。
mavlink_sequence / uart_bytes_total原始 MAVLink 帧序号；当前进程已读 UART 字节累计，包含未识别消息、坏 CRC、未输出的 NaN 帧。MAVLink 序号针对发送链路的全部消息，并非仅 ATTITUDE；忽略消息也会形成表面序号间隙。此累计不包含内核丢失字节，不等于完整性证明。

生产数据合同还需要采集会话 ID、板/飞控启动纪元、校准版本和流健康状态。当前没有 TIMESYNC、时钟偏差/漂移估计、姿态插值或 ToF 姿态补偿；不要直接把两种 source_time_us 相减进行融合。

4. 仍然存在的实现边界

UART、I²C 和日志竞争

采集器仍为一个同步循环。一颗传感器的整帧 I²C 读取与 ULD 解码期间不接收 UART；调用间的有界 drain 缩短积压，但不保证零溢出。UART 在双传感器初始化期间已打开但未 drain，开机累积字节也可能保留；必须测启动后的数据新鲜度。本版不主动请求飞控消息速率、不发送控制指令、没有串口独占或原 termios 恢复策略，也没有 UART 静默超时。

stdout 对 Linux 管道的控制是“完整行成功或明确失败退出”，没有队列和静默丢帧。对普通文件设置 O_NONBLOCK 不能保证磁盘 write 不阻塞；终端/其他类型输出可能短写，此时返回 6，消费者需舍弃末尾不完整行。stderr 的启动/失败日志仍同步；拥塞的 stderr 也可能拖慢启动或退出。当前方案适合有人观察的 GUI 采集，不能把 SSH/GUI 作为飞行控制链路的必要环节。

I²C 分块最大载荷为 256 字节。内核适配器能力、实际时钟、超时/恢复方式需实物核实。期限检查不能抢占 ioctl；5 秒无新帧检查也只能在循环获得执行后运行。一个卡住的驱动会妨碍两颗传感器与 UART。失败读缓冲区会清零；ULD 对畸形帧的处理仍需专项审计。

质量与几何

采集器保留原始距离、状态、targets、signal、ambient、sigma；不替换无效区、不执行估计。现有 app/data.py::valid_distances 只接受 status∈{5,9} 且距离>0，尚未利用 targets、sigma、信号或环境光。此代码现状不能证明其质量门限适合导航；应按实际 ST ULD 版本、模块和场景校准状态解释与阈值。

VL53L5CX_NB_TARGET_PER_ZONE=1；每区只保留一个目标结果。最大有效距离、日光/反射率影响、玻璃和角度边界没有实测，不能从 GUI 色标推定有效量程。两颗 8×8 测距需要光学内参、安装外参、区域方向与遮挡校准；它们当前既不输出位置也不保证完整环境可观测性。镜头装甲识别、视觉跟踪、UWB 数据接入均未实现。

  1. 采集不依赖 GUI 消费速度。未来在 Nano 上保存最近可用样本与健康状态，旁路诊断日志使用有界队列；可覆盖的是明确约定的旧样本，丢弃计数和完整消息边界必须可观测。当前 fail-fast stdout 不能直接替代自主运行的数据总线。
  2. 相机使用明确的有限队列。记录曝光/采集时间、推理开始/结束、后处理结束和送达时间；实时伺服通常应显式拒绝过期目标，防止以处理完所有历史帧为代价累积延迟。NPU 不能免除预处理、解码、后处理、CPU 内存带宽和同步开销。
  3. 定位与视觉交换有时间和质量的数据。定义时间纪元、最大允许龄期、校准版本、坐标系、单位、协方差/置信度和失效标志。估计器按照测量时间融合；视觉输出不能因置信度为正就被无限期复用。optional UWB 同样需要独立时间和健康合同。
  4. 验证定制飞控的实际接口。针对 board_id=7140 / v1.15.0-6-gb8c6373f7f 检查接收消息、坐标系、频率、时间戳、模式与数据源丢失时行为。主线 PX4 的示例只可作为待核对参考。MAVLink 接口只接收姿态与心跳。

PC 可以验证数学、消息合同、故障状态机和 GUI 离线操作；无法回答 SG2002 上“视觉+定位是否同时跑得动”。板上最少要分别测采集、推理、估计与组合负载，再加入持续日志和真实相机输入，报告 p50/p95/p99 时延、最大样本龄期、丢帧、UART 积压/错误、CPU、内存、温度及长时间漂移，才可确定频率和缓冲策略。

退出码含义
0正常停止且清理成功；定位输出和串口流健康度见对应日志。
1传感器打开、探测、初始化/启动失败，初始化期间中断，或信号处理器安装失败。
2CLI 参数无效。
3单实例锁被占用或锁不可用。
4运行中传感器 readiness/读取失败、无新帧 5 秒、循环等待失败；原本正常退出时 stop 失败。
5UART 打开/配置或运行中接收失败、断开。
6stdout 配置、记录缓冲、拥塞、断开或短写错误；原本正常退出时 flags 恢复失败。

采集失败后应由上层将整个采集会话标记为失败；清理不会把已有失败改为 0。启动后 SIGINT/SIGTERM 通常可以正常退出；若信号恰好中断 I²C，锁存取消可使退出码为 4。stop 失败明确表示传感器硬件停止状态未确认。无法把这个过程当作飞控安全动作。

7. 尚未进行的硬件门槛

  1. 确认 Nano 镜像、RISC-V ABI、I²C adapter 能力/时钟/超时、引脚、电平与两颗模块实际寻址。独立总线或事先分配的不同地址仍是当前要求；程序不操作未知 LPn GPIO。
  2. 实测 firmware 加载、启动和停止时延，以及断线、I²C NACK、驱动阻塞、SSH 消费暂停、串口静默和进程终止的行为。通过数据合同记录启动纪元和健康状态。
  3. 校准 ToF 内外参、区域方向、目标状态、量程与环境边界；定位前定义 FC/Nano/相机/UWB 时钟映射和数据龄期门限。
  4. 核实当前定制飞控身份和协议，以台架只接收数据先验证。相机模型、实际分辨率、预处理和 NPU 部署路径确定后再进行板上并发测试。
