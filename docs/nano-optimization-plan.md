# Nano 算法性能优化计划

## 执行顺序

| 步骤 | 修改内容 | 验收依据 |
|---|---|---|
| 1 | 将周期搜索移入低优先级工作线程；主线程收集观测并发布完整模型 | observe/merge 不执行搜索；最多一份未完成任务；旧配置结果丢弃；新观测与时间戳不回退 |
| 2 | 复用搜索分桶容量，预计算样本相对时间，以减去整周期计算非负相位 | 保留 0.8–10 s 搜索范围、0.02/0.0025 s 步长、中位数统计与验证门限；相同输入的有效预测数值一致 |
| 3 | 在 Nano 上比较原程序、优化后的同步模式与后台模式 | 同一图像、地形和观测文件；记录单轮 P99/最大值、导航/视觉频率、CPU、内存、温度和预测误差；60 s 对照与 180 s 持续测试 |

## 调度实现

控制目标为 IMU 预测 100 Hz、导航 50 Hz。视觉在 nice=5 的线程执行，保留最新待处理帧；ToF 每个方向保留最新帧，只在导航发布后融合一帧。控制按 20 ms 槽位发布，晚到时跳过积压槽位。周期模板在发布前验证新增观测，并禁用局部异常相位。

板端性能、预测误差与截止时间统计见 [视觉与 ToF 调度测量](nano-scheduling-20261015.md)。

## ToF 与运动变化检测

ToF 缓存安装射线、每帧旋转和地图求交中的重复量。原实现与缓存实现对照 20,000 条射线和 1,500 次融合，命中与接收判定一致，数值差异处于浮点舍入量级。

周期预测按独立曝光和共享采样检查残差。单次超限暂停预测，两次正常观测恢复；三次同向异常跨越至少 40 ms 时重置学习窗口，旧窗口的后台结果丢弃。同一曝光派生的连续预测与重复广播不会重复确认异常。

计算负载、全回放误差、预测覆盖率和重学时长见 [运动变化检测与 ToF 测量](nano-motion-guard-20261015.md)。

## 独立曝光与来源一致性

学习器每次曝光只接收一次关联后的原始位置，延迟观测按曝光时间插入，重复数据不增加权重。共享变化检测保留来源，对同刻来源使用残差中位数；陈旧点不掩盖新异常。模型暂停后继续确认变化，新模板发布不清空尚未确认的异常。重置边界之前的整窗广播数据不得重新进入窗口。

数值、覆盖率与恢复时间见 [曝光一致性](nano-observation-consensus-20261015.md) 和 [独立曝光学习](nano-independent-learning-20261015.md)。

## 槽位与像素计算

ToF 只在导航发布后的槽位启动，核验融合开始/结束时间、输入帧龄与替换次数，见 [导航槽位测量](nano-navigation-slot-20261015.md)。

像素颜色比例采用 8 位通道查表，连通域使用同一颜色掩码保存访问状态，保留颜色阈值、几何配对及 PnP 判据。逐值颜色测试与原实现图像对照见 [像素颜色计算](nano-color-kernels-20261015.md)。

## 后续验证

1. 核验每次 20 ms 导航截止时间；平均 50 Hz 与尾部延迟分别检查。
2. 用真实相机序列核验 ROI、分辨率与检测分支选择，比较漏检率、位置误差和帧龄。
3. 验证相位重对齐能否缩短当前约 14 s 的重学等待，保留停转、变速和变形时的失效检测。
4. 在闭环仿真中检查改用独立曝光后，短时单机视觉窗与多机共享的相位覆盖、轨迹和接触判定。
5. 在接触后恢复中核验飞控着地反馈、传感器中断与出界状态；失效输入约束和全队恢复验证见 [外部里程计失效与全队恢复](nano-recovery-20261015.md)，制导对照见 [终端制导与失效恢复](nano-contact-guidance-20261015.md)。
6. 检查短距横向追赶能力与过板退避时机，复核进入降落后的复飞禁止和飞控消息有效期。提交门限、重返入口和降落超时验证见 [俯冲重试与降落超时](nano-dive-retry-20261015.md)，入口对准对照见 [滑轨预测与入口对准验证](nano-entry-prediction-20261015.md)。
7. 分离终端定位偏差、速度估计和运动响应，核验接触后姿态恢复及独立降落等待。返航航点门限和原始收包状态验证见 [返航航点收敛与地形接触](nano-return-route-20261015.md)，过板对照见 [终端横向误差与过板退避](nano-plane-exit-20261015.md)。
8. 核验出界后的定位有效性、物理承接面和失控检测。飞控消息有效期、49 秒降落阻塞统计及起降回归见 [飞控反馈有效期与降落等待](nano-landing-feedback-20261015.md)。
9. 对照电机命令、实际关节转速与物理位移，定位偶发的高输出未离地；持续检查未起飞成员的地面等待和全队恢复期间的启动请求。执行记录器与混合起飞验证见 [起飞执行反馈与中止返航](nano-takeoff-actuation-20261015.md)。
10. 检查短于心跳有效期的控制中断，核验恢复后停止任务参考与原生降落。1.8 秒进程暂停对照和 500 ms 发送间隔检查见 [OFFBOARD 控制流连续性](nano-offboard-continuity-20261015.md)。
11. 核验航向误差在光流融合中的传播，继续处理接触失败与定位失效后的独立降落。数值差分回归、两次接触返航对照见 [光流融合中的航向不确定度](nano-flow-yaw-20261015.md)。
12. 新俯冲必须在协调器的剩余接触时窗内保留完整尝试上限和导航周期，继续核验未命中后的退出与下一轮切换。截止时间、短时窗和默认任务验证见 [接触时窗与俯冲提交](nano-contact-deadline-20261015.md)。
13. 提交时检查前向速度与三轴限速比例、垂向运动方向，保持提交范围外的接近准备。速度边界、两组闭环与出界下落记录见 [终端提交的运动条件](nano-terminal-entry-20261015.md)；继续分开核验未命中后的碰撞恢复和原生着地停机。
14. 近目标比力扰动等待压力确认，未确认时退出前推并恢复姿态；扩大正常减速负样本，继续处理重试高度和横向偏差。60 ms 确认等待、压力取消、原生姿态输入和两组返航停机验证见 [未确认冲击的姿态恢复](nano-inertial-recovery-20261015.md)。
15. 将入口几何、到达预测和飞控响应一起验证，避免把参考限幅等同于轨迹收敛。单独前向限速的两组对照见 [终端前向参考上限对照](nano-forward-cap-20261015.md)；提前提交组合未取得合格接触，见 [入口轨迹与观测方差](nano-entry-uncertainty-20261015.md)。
16. 传播曝光位姿的完整位置、航向及交叉协方差，分别处理 PnP 和绿色引导的几何模型；以矩阵观测噪声更新目标跟踪。数值差分、板端耗时、同序列误差与三组默认地图闭环见 [曝光位姿协方差与目标跟踪](nano-vision-uncertainty-20261015.md)。合格接触为 2/4、4/4、3/4；继续核验全队成功率的重复性。
17. ToF 地形索引使用 8 面叶子和匹配的遍历预算，保留几何与融合判据。微基准、118 万条轨迹射线、60 秒对照和 180 秒负载见 [ToF 地形射线索引与板端负载](nano-ray-traversal-20261015.md)。ToF 单帧 P99 降至约 9.3–9.5 ms；索引对照中的视觉约 29 Hz，导航间隔尾部超过 20 ms。
18. 像素与 PnP 共享 RGB 扫描，按各自门限生成独立掩码，并提前排除两条链均不会接受的背景。35,323,904 个颜色与配置组合及三轮图像流水线对照一致；60 秒 CPU 为 79.13%，180 秒视觉保持 30 Hz、无待处理帧替换。导航间隔 P99 仍约 20.77 ms，两组闭环分别在起飞和失效降落阶段中止，见 [RGB 共享扫描与 Nano 视觉负载](nano-shared-color-scan-20261016.md)。
19. 对齐伴随日志与 PX4 原生时钟，追踪位置、速度新息超限前的外部里程计、曝光协方差和光流观测；分别验证 Navigation failure、Land 请求被拒绝与出界的因果链。保留原生着地停机确认，继续核验目标跟踪滞后和全队闭环重复性。
20. 使用 SDLOG_PROFILE=3 保留全速估计器输入，按各机首次原生解锁时间审计回放时间戳。八份飞行区间的索引输入完整；原生回放状态仍未与记录数值一致，外部航向融合对照也未证明全队可靠性收益。日志检查、四组闭环和回放差异见 [PX4 原生估计输入与回放检查](nano-native-replay-20261016.md)。
21. 按历史 IMU 四元数补偿 ToF 缓存帧曝光姿态，保留当前地图航向修正；缺失历史时拒绝对应帧。主机双构建、Nano 回归与三轮解析旋转对照通过；两次闭环为 4/4、3/4，均原生着地停机。180 秒负载视觉完成 5,397/5,400 帧、CPU 80.37%，严格 20 ms 导航仍未通过，见 [ToF 曝光姿态补偿与 Nano 测量](nano-tof-attitude-20261016.md)。继续核验 runner 中姿态与 IMU 的源时间对齐，以及视觉提交拒绝原因。
22. 将视觉统计扩容、旧请求和旧结果释放移出消息临界区，分别计数时间戳无效与锁忙。Nano 180 秒完成 5,398/5,400 帧，2 次拒绝均为锁竞争，未证明稳定吞吐收益；runner 已有下一导航周期重试。双构建、Nano 回归与 3/4 合格接触后的四机原生停机检查通过，见 [视觉消息锁与提交拒绝测量](nano-vision-mailbox-20261016.md)。继续检查姿态源时间、控制间隔尾部和全队闭环重复性。
23. 按姿态源时间及机体系陀螺采样 IMU 姿态，采用有界 SLERP 和四元数外推；源时间倒退不进入预测。旧 runner 的 UDP 时间错配用例失败，新实现双构建和 Nano 回归通过，板端查询均值约 1.6–1.9 µs。两组闭环为 1/4、3/4，前一组四机控制流中断后就地降落，见 [IMU 与姿态源时间对齐](nano-imu-epochs-20261016.md)。用真实原生日志验证变角速度下的外推误差，继续定位运行时停顿、首包时钟映射与加速度旋转所用航向的时序。
24. 八架次原生数据构造 96 种时序，包含姿态重置不匹配点。当前外推的汇总角度 RMSE 为 0.373°，保持姿态为 0.953°；积分候选为约 0.210°、最大误差更小，但 12 组 RMSE 退化，需记录实际输入包并核对陀螺平均窗口。数据与模型比较见 [IMU 动态误差与控制线程时序](nano-imu-dynamics-20261016.md)。
25. 机体加速度使用本条 IMU 更新后的地图航向，保留已有地图修正；旧 UDP 用例失败，新实现双构建及 Nano 回归通过。Nano 航向查询约 0.167 µs，两组闭环为 3/4、4/4且四机均返航停机。按需阶段计时测得循环最大 124.030 ms、对应线程 CPU 3.408 ms，观测、相机和日志路径有低 CPU 等待。继续确认文件 I/O 与调度原因，再处理控制线程同步等待；严格 20 ms 和稳定全队成功率仍需核验。

26. 主线程跟踪确认日志和相机元数据具有同步访问成本；日志改为导航周期发送控制后统一刷新，受控消息写调用由 220 次降为 17 次，记录顺序与退出末尾完整。双构建回归通过；两组闭环均为 3/4、四机原生停机，第二组 0 号卡住后就地降落、未返航。相机阶段最大 52.315 ms，另有 461.705 ms 的低 CPU 循环停顿尚未定位；路径探测位于相机计时之外，继续覆盖该调用并区分文件访问和调度。测量见 [控制线程文件访问与日志刷新](nano-runtime-io-20261016.md)。

27. 独立路径计时在四机同一时刻捕获 487.804–503.402 ms 的相机目录探测等待，并触发控制流保护。目录探测和 JSON 读取已移至元数据线程；旧 runner 的 FIFO 阻塞回归失败，新版在约 0.8 s 后台读取等待时仍输出导航状态，主线程相机文件调用为零。双构建和 Nano 单元测试通过，两组闭环均为 4/4、四机返航原生停机，循环最大 19.718/9.550 ms。视觉帧龄中位数增加约 16–22 ms，继续优化交接时机并独立测量导航发布间隔。第一组 2 号 ULog 缺少一条 EKF2 引用的外部里程计记录，输入完整性为失败；其余七架次通过。见 [相机目录等待与异步元数据](nano-camera-metadata-20261016.md)。

28. 记录导航判定与 UDP 参考提交的单调时钟，直接测量相邻间隔；约 0.8 s 暂停仍触发原控制流保护。元数据请求提前到导航前 6 ms，保持 20 ms 槽位与有界异步交接，双构建回归通过。任务组帧龄中位数降低 10–14 ms，但接触仅为 2/4，基线为 1/4；重复组因 2 号原生健康检查拒绝解锁而在起飞阶段中止。导航 P99 约 20.1–20.2 ms，预取组有约 26.4 ms 长尾，严格 20 ms 未通过。优先检查 2 号传感器 STALE、初次接触准备、导航长尾和原生里程计日志缺失。见 [元数据预取与导航发布间隔](nano-camera-prefetch-20261016.md)。

29. 原生 STALE 定位为静止加速度重复值判定，失败机采样时戳持续更新；原版校验库回放 1,001 条实际输入触发 967 次 STALE、无采样超时。micro 的 IMU 与气压计补齐 PX4 x500 原生噪声剖面，参数和健康门限保持原值；13 项模型回归与 SDF 检查通过。八段新静止输入均无 STALE，冻结故障及停止输入仍被检出。两组四机均起飞并原生返航停机，接触为 4/4、2/4；全队成功率和严格 20 ms 仍未达标，一份日志仍缺外部里程计引用。继续核验初次接触准备、IMU/世界时钟对齐和输入记录完整性。见 [micro 静止传感器 STALE 与噪声配置](nano-native-sensor-noise-20261016.md)。

板端回放测量算法计算；传感器采集、链路延迟和飞控执行需通过接入真实设备的测试另行测量。
