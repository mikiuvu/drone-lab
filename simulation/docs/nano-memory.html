内存结论

当前 C++ 灯条/PnP、定位与有界帧缓存方案从预算上可行；尚无实板运行数据，不能确认实际镜像上有足够余量。256 MiB 是物理内存，不是应用可用内存。

OpenSBI0.5 MiB固件区域
剩余上限约140.7 MiB还包括内核、服务和应用，不能全给算法

若内核服务占40 MiB、应用峰值预算55 MiB，则约剩45.7 MiB；若二者分别55和80 MiB，则只剩5.7 MiB。这些是情景预算。主机微基准22.8 MiB RSS已包含加载地图，地图4.89 MiB不能再重复加到该RSS上；真实板端库、ISP驱动、帧池和峰值不同。

640×360 RGB单帧约0.659 MiB，双帧约1.318 MiB；GC4653原始分辨率、stride、VB池数量及格式需独立核算。ION内部相机池不能又计入Linux应用RSS。当前没有NPU模型；以后模型/张量会增加需求。桌面Qt/Gazebo不部署在Nano。

最终确认需同一镜像启动相机、三ToF、UWB和实际C++任务，采集/proc/meminfo、/proc/PID/smaps_rollup、ION/VB使用量、OOM日志和温度；至少持续10分钟并覆盖失锁重识别。普通Linux内存与ION两个区域都需留余量。

触压判定与门限

原装甲板碰撞传感器作为二值触压开关。命中只由触压上升沿确认，不由IMU推断；该通道只传接触事件，不向定位提供板位置。仿真反馈通道是测试设施，实机比赛是否能接收场地命中反馈需按规则与接口核实。当前无标定接触面积，故不宣称测得Pa或N。

采用较宽门限作为当前默认；小样本不足以证明长期100%成功率。放宽的是视觉推进对准容差，不是触压成功标准，也未把周期预测低置信结果当作真实观测。
